The idea

The model never does arithmetic. Every total, share and comparison comes from a pandas tool, and every answer is checked against those tool results before you see it.

About

How it works.

Upload → Parser Agent (rules, with a model fallback for unusual column layouts) → Categorizer Agent (keyword rules, then a few-shot prompt for unknown merchants) → a pandas DataFrame that is the source of truth for numbers, plus a ChromaDB collection with one document per transaction.

Each question → rewriter (chat memory) → intent router (LCEL with structured output) → Lookup chain, Analysis Agent, Advisor Agent or a scope reply → reflection number check → answer and trace.

Semantic search finds which transactions are relevant; pandas computes how much. Similarity search returns only the top few matches, so it is never used to compute a total.

Privacy

Embeddings run locally (all-MiniLM-L6-v2). The Parser masks account numbers, card numbers, UPI IDs and reference numbers. The model sees merchant names when categorising and tool results when answering, never the full statement. Advice is general budgeting guidance, not professional financial advice.
